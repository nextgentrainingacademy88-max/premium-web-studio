# i18n.md - trilingual with data-i18n + prerender.mjs

The system ships EN + `zh` + `ms` from ONE English source page. You mark copy with `data-i18n`, write
per-language JSON dictionaries, and a dev-only Node script bakes real static language pages. The
runtime (`i18n.js`) only wires the language switcher on baked pages; it translates live on the un-baked
EN source so you can preview a language while authoring.

## The markup contract

```html
<html lang="en">                                    <!-- current language -->
<h1 data-i18n="hero.title">English text</h1>        <!-- textContent set from the key -->
<div data-i18n-html="hero.rich">English <em>HTML</em></div>   <!-- innerHTML set from the key -->
<button data-lang-switch="zh">中文</button>          <!-- click -> navigate to the /zh/ sibling -->
```

- `data-i18n` -> replaces text content. Use it on LEAF text nodes.
- `data-i18n-html` -> replaces inner HTML. **Leaf-ish only**: the element must not contain nested
  same-tag children (a `<ul>` full of `<li>` will break the baker's regex - put `data-i18n` on each
  `<li>` instead). Inline `<strong>/<em>/<a>` that are the only content are fine.
- `data-i18n-content` -> replaces the tag's `content=""` ATTRIBUTE (bake-time only, for
  `<meta name="description">` and `og:*` tags, which have no inner text to stamp).
- `data-lang-switch="<lang>"` -> the switcher. The current lang gets `aria-current`.

Keys are dot-paths into nested JSON. Missing keys are left as the English source (graceful).

## Dictionaries

Two layers, deep-merged with the site overriding the shared:

```
shared/i18n/zh.json   shared/i18n/ms.json     # shared strings (nav, chrome, common CTAs)
<site>/i18n/zh.json   <site>/i18n/ms.json     # per-site overrides (optional)
```

```json
{ "hero": { "title": "字幕标题", "sub": "..." }, "nav": { "pricing": "价格" } }
```

Either file may be missing (tolerated). The site file wins on shared keys.

## Baking - `node shared/prerender.mjs <dir>`

Run from the project root. `<dir>` is `.` for the hub or a subsite dir name:

```bash
node shared/prerender.mjs .                    # the hub
node shared/prerender.mjs trainer-leadership   # a subsite
```

For each target lang (`zh`, `ms`) it:
1. Reads `<dir>/index.html` (the EN source of truth).
2. Loads `shared/i18n/<lang>.json` then `<dir>/i18n/<lang>.json` (merged).
3. Stamps `data-i18n` text + `data-i18n-html` HTML + `data-i18n-content` content attributes from
   the dictionary (missing keys keep English).
4. Swaps `<html lang="en">` -> `<html lang="<lang>">` and adds `data-i18n-baked`.
5. Rewrites relative `href`/`src` by prefixing one `../` (the baked file lives one dir deeper, at
   `<dir>/<lang>/index.html`). An absolute `rel="canonical"` / `og:url` ending in `/` gets
   `<lang>/` appended so each baked page self-canonicalizes.
6. Injects `<link rel="alternate" hreflang>` for en/zh/ms + x-default.
7. Writes `<dir>/<lang>/index.html`.

It also patches the EN source in place with its own hreflang block (idempotent - re-running is
byte-stable). The baked pages are generated output; the `.gitignore` excludes `*/zh/` and `*/ms/`.

## URL model + the switcher

- **EN = no prefix** (`/`, `/about/`), **zh = `/zh/...`**, **ms = `/ms/...`**.
- The switcher strips a leading supported-lang segment, then prefixes the target (EN adds nothing),
  preserving `?query` + `#hash`. So `/zh/pricing` -> click BM -> `/ms/pricing`, click EN -> `/pricing`.

Wire the runtime once per page:

```html
<script src="../shared/i18n.js"></script>
<script>
  if (window.NGI18n) NGI18n.init({ base: './i18n/', shared: '../shared/i18n/', langs: ['en', 'zh', 'ms'] });
</script>
```

On a baked page (`data-i18n-baked`) this ONLY wires the switcher (skips fetch + DOM walk - the strings
are already stamped in). On the EN source it fetches the dictionaries and stamps live for preview.

Note the hub sits at the root, so its `shared:` path has no `../` (`'./shared/i18n/'`); subsites use
`'../shared/i18n/'`.

## Hreflang note

Hrefs are RELATIVE (the deploy domain is unknown at build time), which crawlers tolerate. If you wire
a canonical origin, swap them to absolute URLs.

## Font note

Add `Noto Sans SC` to the font load for a page that ships `zh`; `--font-body` already lists it as a
fallback so CJK glyphs render cleanly.
